## Implementation Plan (Pre-Implementation)

### Approach

1. Add `@qa-automater/database` package with Prisma Migrate, connection pool utilities, and verification scripts.
2. Extend Docker Compose with PostgreSQL 16 (pgvector image), PgBouncer, health checks, and persistent volumes.
3. Wire NestJS API `DatabaseModule` with startup pgvector verification and `/health` database checks.
4. Add CI job for migrations + pgvector verification via Docker Compose.
5. Scaffold AWS RDS Multi-AZ Terraform module for staging/production.

| Area | Impact |

## Summary of Work Completed

### Database Infrastructure

- PostgreSQL 16 via `pgvector/pgvector:pg16` with `max_connections=100`, logging enabled
- Persistent volume `postgres_data`
- Health check via `pg_isready`
- AWS RDS Multi-AZ Terraform scaffold with backups, monitoring, Secrets Manager

### pgvector

- Extension enabled in Docker init script and Prisma migration
- `app.pgvector_health_check` table with `vector(1536)`
- `verifyPgvector()` + API startup verification via `DatabaseService.onModuleInit`
- Fail-fast in migration if extension missing

### Migration Framework

- **Prisma Migrate** with initial migration `20260718120000_e1_2_init_pgvector`
- Idempotent SQL (`IF NOT EXISTS`, conditional inserts)
- Scripts: `pnpm db:migrate`, `pnpm db:migrate:dev`, `pnpm db:verify`
- Documentation in `packages/database/docs/migrations.md`

### Connection Pooling

- PgBouncer transaction mode on port 6432
- `docker/pgbouncer/pgbouncer.ini` with pool sizing and timeouts
- Application `pg` Pool via `createDatabasePool()` with env-based config
- Health checks in Docker and API `/health`

### Security / RLS Scaffold

- `app.set_org_context()` / `app.current_org_id()` functions
- `app.rls_scaffold` placeholder table (`enabled=false`)
- Documentation in `packages/database/docs/rls-scaffold.md`

### Configuration

- `.env.example` updated with pool/migrate URLs and pool sizing
- Terraform Secrets Manager for RDS credentials

### Development Environment

```bash
pnpm db:up      # Postgres + PgBouncer + Redis
pnpm db:migrate # Apply migrations
pnpm db:verify  # Migrate + pgvector + connection budget check
```

### AC1 — Staging migrations + pgvector

**Given** staging environment **When** migrations execute **Then** PostgreSQL available, pgvector exists, migration succeeds.

| Check | Result |
|-------|--------|
| Migration SQL creates pgvector | ✅ `CREATE EXTENSION IF NOT EXISTS vector` |

| Check | Result |
|-------|--------|

| Verify script checks active connections | ✅ `checkConnectionBudget()` |
| `/health` reports pooled=true | ✅ `HealthController` |
| Unit tests | ✅ 4 API tests + 2 database tests pass |

## Environment Variables Added

| `DATABASE_POOL_URL` | Runtime via PgBouncer | `...@localhost:6432/qa_automater` |
