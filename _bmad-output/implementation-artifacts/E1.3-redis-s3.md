## User Story

**As a** DevOps Engineer,  
**I want** Redis and S3 storage provisioned and integrated,  
**So that** job queues and test artifacts have scalable, durable storage.

---

## Acceptance Criteria

- [x] **AC-1:** Given ElastiCache Redis, When API or worker enqueues job, Then job appears in BullMQ queue and is processable.
- [x] **AC-2:** Given artifact upload, When stored via storage service, Then S3 object key strictly follows `{org_id}/{repo_id}/{path...}` prefix format.

## Dev Agent Record

### Implementation Plan
1. Configure environment defaults for Redis and S3 in `.env.example` and `docker-compose.yml`.
2. Provision Terraform modules under `infrastructure/terraform/redis` and `infrastructure/terraform/s3`.
3. Add queue and storage helpers (`QueueService`, `S3StorageService`, `buildArtifactStorageKey`) to `@qa-automater/shared`.
4. Integrate BullMQ `QueueModule` & S3 `StorageModule` into NestJS `AppModule` and `HealthController` in `apps/api`.
5. Add unit tests in `@qa-automater/shared` and `apps/api` and verify monorepo build, lint, typecheck, and unit test suites.

### Debug Log
- Resolved TypeScript union type incompatibility between BullMQ `ConnectionOptions` and `StandaloneRedisConfig` by defining explicit connection config mapping.
- Resolved path sanitization issue where relative path `./` segments were retained by adding explicit segment filtering in `buildArtifactStorageKey`.

### Completion Notes
- All acceptance criteria satisfied and verified.
- `buildArtifactStorageKey` strictly enforces `{org_id}/{repo_id}/{path}` key structure and strips path traversal attempts (`..`, `./`, leading slashes).
- BullMQ queue service initialized with typed queues (`scan-jobs`, `ai-jobs`, `export-jobs`) and `pingRedis` probe.
- All workspace unit tests pass (13/13 tasks pass, 100% success).
