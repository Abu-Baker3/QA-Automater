**Priority:** High  
**Points:** 5  
**Status:** done

## User Story

**As an** SRE,  
**I want** distributed tracing and metrics telemetry,  
**So that** I can debug cross-service failures between API, BullMQ queues, and background workers.

---

## Acceptance Criteria

- [x] **AC-1:** Given an API request enqueuing a scan or AI job, When worker processes it, Then a single distributed trace spans `api` → `queue (BullMQ)` → `worker`.
- [x] **AC-2:** Given observability monitoring (CloudWatch/Grafana), When viewing metrics dashboard, Then scan duration, job execution duration, and queue depth metrics are collected and visible.

---

## Technical Specifications

| Service | Instrumentation Target | Exporter / Metric |
|---|---|---|
| `@qa-automater/shared` | Core OTel SDK & Tracing Utility | Shared OTel initialization helper |
| `apps/api` | NestJS HTTP server & BullMQ Enqueue | HTTP Tracing, Express middleware, BullMQ job metadata context propagation |
| `workers/scan` | Node.js Worker & BullMQ Processor | Job processing trace extraction, AST scan duration metric |
| `workers/ai` | Node.js Worker & BullMQ Processor | AI job duration & LLM request trace extraction |
| `workers/export` | Node.js Worker & BullMQ Processor | Export job trace extraction & duration metrics |

## Dev Notes

- **Architecture Reference:** `System Architecture §11 Observability (OpenTelemetry → Grafana/CloudWatch)`
- **Trace Context Spec:** W3C Trace Context standard (`traceparent` header / payload format).
- **Environment Variables:**
  - `OTEL_SERVICE_NAME` (e.g., `qa-api`, `qa-worker-scan`)
  - `OTEL_EXPORTER_OTLP_ENDPOINT` (e.g., `http://localhost:4318` or OTLP collector endpoint)
  - `OTEL_TRACES_SAMPLER` (default `always_on` for dev/staging, `parentbased_traceidratio` for prod)
