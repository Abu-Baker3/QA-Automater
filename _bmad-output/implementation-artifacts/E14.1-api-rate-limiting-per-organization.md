# Implementation Artifact: E14.1 API Rate Limiting per Organization

## Story Details
- **Story Identifier**: `E14.1`
- **Epic**: Epic 14 — Security, Observability & Operations
- **User Story**: As the **Platform**, I want rate limits, so that abuse and LLM cost overruns are prevented.
- **Status**: Implemented & Verified
- **Date**: 2026-08-29

## Acceptance Criteria Summary

- **AC1: Given free tier When >10 generation jobs/hour Then 429 returned**:
  - Implemented `RateLimiterService` (`apps/api/src/rate-limiting/rate-limiter.service.ts`) with sliding-window quota tracking per organization (`checkOrgGenerationLimit`).
  - Free tier is capped at 10 generation jobs per hour. The 11th request throws an `HttpException` with HTTP status `429 Too Many Requests`.
  - Integrated quota enforcement directly into `GenerationJobsService.startGeneration`.

- **AC2: Given API calls When >100 req/min/user Then 429 with Retry-After header**:
  - Implemented per-user/client sliding window rate limiter (`checkUserRateLimit`).
  - Created `RateLimitGuard` (`apps/api/src/rate-limiting/rate-limit.guard.ts`) populating standard telemetry headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`).
  - When request volume exceeds 100 req/min, sets `Retry-After: <seconds>` response header and throws HTTP 429.
