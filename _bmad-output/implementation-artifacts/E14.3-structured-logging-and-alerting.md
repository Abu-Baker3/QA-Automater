## Story Details
- **Story Identifier**: `E14.3`
- **Epic**: Epic 14 — Security, Observability & Operations
- **User Story**: As an **SRE**, I want alerts on failure rates, so that incidents are detected early.
- **Status**: Implemented & Verified
- **Date**: 2026-08-29

## Acceptance Criteria Summary

- **AC1: Given scan failure rate >5% over 1h When threshold breached Then PagerDuty alert fires**:
  - Implemented `AlertManager` ([`packages/shared/src/telemetry/alerting.ts`](file:///c:/Users/abch6/Desktop/QA%20Automater/packages/shared/src/telemetry/alerting.ts)) with sliding 1-hour window tracking (`recordScanOutcome`, `getScanMetrics`, `checkScanFailureAlert`).
  - When repository scan failure rate exceeds 5% (`> 0.05`) over the 1-hour window, automatically generates and dispatches a PagerDuty Event v2 payload (`severity: 'error'`, `component: 'scan-pipeline'`).
  - Automatically prunes events older than 1 hour.

- **AC2: Given LLM error rate >2% When threshold breached Then alert fires**:
  - Implemented LLM call sliding-window error tracking (`recordLlmOutcome`, `getLlmMetrics`, `checkLlmErrorAlert`).
  - When LLM call error rate exceeds 2% (`> 0.02`) over the 1-hour window, automatically fires a critical SRE / PagerDuty alert (`severity: 'critical'`, `component: 'llm-service'`).

- **Structured JSON Logging**:
  - Implemented `StructuredLogger` providing standardized JSON formatted log entries with trace/span context (`timestamp`, `level`, `service`, `event`, `message`, `error`, `attributes`) and automated token/secret redaction.
