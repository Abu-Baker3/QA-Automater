## Acceptance Criteria Summary

- **AC1: Given CI on main When eval runs Then 20 golden stories across 5 repos evaluated**:
  - Implemented `GOLDEN_STORIES_DATASET` ([`packages/shared/src/llm/golden-stories-dataset.ts`](file:///c:/Users/abch6/Desktop/QA%20Automater/packages/shared/src/llm/golden-stories-dataset.ts)) comprising 20 golden user stories distributed across 5 open-source repositories:
    1. `nextjs-e-commerce` (4 stories: User Login Flow, Add Product to Cart, Search Catalog, Multi-step Checkout)
    2. `react-admin-dashboard` (4 stories: Filter Users Table, Update User Role, Dark Mode Toggle, Edit Profile Settings)
    3. `remix-saas-starter` (4 stories: Switch Organization, Invite Team Member, Upgrade Subscription Plan, Generate API Key)
    4. `vue-todomvc` (4 stories: Create Todo Item, Mark Todo Completed, Clear Completed Todos, Filter Active Todos)
    5. `svelte-blog-cms` (4 stories: Publish New Article, Save Post Draft, Filter Articles by Tag, Submit Post Comment)
  - Implemented `GoldenEvalHarness.runEvaluation()` ([`packages/shared/src/llm/golden-eval-harness.ts`](file:///c:/Users/abch6/Desktop/QA%20Automater/packages/shared/src/llm/golden-eval-harness.ts)) to iterate through all 20 golden stories and evaluate locator mapping accuracy across 30 total steps.

- **AC2: Given locator precision When below 80% Then CI fails blocking deploy**:
  - Implemented locator precision threshold checking (`min_locator_precision: 0.80`).
  - Automatically calculates overall locator precision `(correct_mappings / total_steps)` and per-repo precision breakdowns (`RepoEvalBreakdown`).
  - Throws `GoldenEvalRegressionException` when overall locator precision falls below 80% (0.80), blocking CI and deployment pipelines.
  - Implemented CLI runner script `packages/shared/src/llm/run-golden-eval.ts` exposed via `pnpm eval:ai`.
  - Integrated `pnpm eval:ai` step into `.github/workflows/ci.yml` and `.github/workflows/deploy.yml`.
