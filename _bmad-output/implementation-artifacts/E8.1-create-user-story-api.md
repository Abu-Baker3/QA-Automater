# Implementation Artifact: E8.1 Create User Story API

## Story Details
- **Story Identifier**: `E8.1`
- **Story Description**: Implement REST API endpoint `POST /repositories/:id/stories` allowing QA engineers to submit user acceptance stories with structured acceptance criteria and validation rules.
- **Status**: Implemented & Verified

## Acceptance Criteria Summary
- **AC1: Valid Payload Submission**:
  - Implemented `POST /repositories/:id/stories` endpoint in `StoriesController` (`apps/api/src/stories/stories.controller.ts`).
  - Protected with `@UseGuards(ClerkAuthGuard, RolesGuard)` and `@Roles('ADMIN', 'MEMBER')`.
  - Returns `201 Created` with `user_story_id` (e.g. `story_a1b2c3d4`), repository link, story details, and structured acceptance criteria array.
- **AC2: Description Length Validation**:
  - `StoriesService` (`apps/api/src/stories/stories.service.ts`) validates `description.length <= 4000`.
  - Submissions with descriptions $> 4000$ characters throw a `400 Bad Request` validation error (`BadRequestException`).
