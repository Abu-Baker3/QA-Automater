## 1. User Story & Acceptance Criteria

### **User Story**
As a QA Engineer, I want to see my submitted stories, so that I can track generation history.

### **Acceptance Criteria**
- **AC1:** Given org stories exist When GET list (`GET /repositories/:id/stories`) Then return title, created_at, linked generation job status (and paginated array of user story items).
- **AC2:** Given story id When GET detail (`GET /stories/:id`) Then return full description and `acceptance_criteria` (or 404 if not found).

---

## 2. Implementation Summary

### **A. Shared Types (`packages/types/src/index.ts`)**
- Added and exported:
  - `UserStoryListItem`: Extracted list item fields with `linked_generation_job_status`.
  - `UserStoryListQueryDto`: Pagination (`page`, `limit`) and title `search` query DTO.
  - `UserStoryListResponse`: Paginated story list response wrapper.
  - `UserStoryDetailResponse`: Full `UserStoryItem` detail response contract.

### **B. Service Layer (`apps/api/src/stories/stories.service.ts`)**
- Implemented `listUserStories(orgId, repositoryId, query)`:
  - Filters in-memory store by repository ID and optional search string.
  - Returns paginated `UserStoryListResponse` with `linked_generation_job_status`.
- Implemented `getUserStoryDetail(orgId, storyId)`:
  - Lookup by `id` or `user_story_id`.
  - Throws `NotFoundException` if no story matches the provided ID (**AC2**).
  - Returns complete story object with full `description` and `acceptance_criteria`.

### **C. Controller Layer (`apps/api/src/stories/stories.controller.ts`)**
- Registered routes:
  - `GET /repositories/:id/stories`: Returns paginated user stories list (**AC1**).
  - `GET /stories/:id`: Returns full user story detail or 404 (**AC2**).
- Secured with `@UseGuards(ClerkAuthGuard, RolesGuard)` and `@Roles('ADMIN', 'MEMBER')`.
